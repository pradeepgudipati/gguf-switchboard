# gguf-switchboard v0.1.7

**Better operations, model diagnostics, and deployment reliability.** This release adds live host and GPU telemetry, expands the Conformance Console into a persistent diagnostic workspace, improves local model management, and fixes several deployment and model-lifecycle failure modes.

## What's new

### Live status and service operations

- Added `ggs status` and `ggs logs` commands for service health, resident-model state, recent journal output, and follow mode.
- Added a live Swagger UI status header showing the resident model, request activity, context size, estimated VRAM, host CPU/RAM, and per-GPU utilization, memory, and temperature.
- Added grouped, capability-aware model selectors and a dedicated Conformance Console link in the Swagger header.
- Added `active_requests`, host telemetry, and detailed GPU telemetry to the `/status` response.

### Conformance Console and tool diagnostics

- Added persistent Inspect, Resolved Template, Battery, and Compare history in a dedicated `conformance.db` SQLite database.
- Added per-tab recent-run tables, full stored response inspection, filtering, deletion, and history clearing.
- Added custom OpenAI-compatible targets for Inspect, Battery, and Compare without persisting API keys or endpoint credentials.
- Inspect and Compare now store explicit PASS/FAIL results, and backend or model-load failures are retained in history instead of disappearing.
- Fixed `/apply-template` and `/props` routing so llama-server diagnostics use the bare server root rather than the OpenAI `/v1` prefix.
- Fixed a scheduler race that allowed the idle priority watcher to unload a model while a conformance request was running.

### Model registry and local model management

- Added `ggs models list` for an indexed inventory of local GGUF and Safetensors models.
- Added `ggs models delete <name|#>` with safe path validation and registry cleanup.
- Improved deployed-registry resolution for vLLM pulls and eliminated ambiguity from stray registry files.
- Registry refresh now preserves stable model aliases and assigns the intended deployed source consistently.

### Deployment and backend reliability

- Fixed vLLM runtime resolution when commands run outside the installation directory.
- Fixed deployed vLLM registry fallback and model-directory permissions.
- Improved `deploy.sh` update detection so unchanged llama.cpp and vLLM runtimes are not rebuilt unnecessarily.
- Switched llama.cpp maintenance to the stable release channel.
- Added automatic GPU-layer reduction after weight-loading OOM failures and persists the successful reduced setting for later starts.
- Improved runtime update tests and deployment smoke coverage.

### Documentation and release quality

- Updated the README with current Swagger status-header screenshots and moved demo media under `docs/assets/`.
- Refreshed model-management, status, logging, deployment, and Conformance Console documentation.
- Updated formatting and Clippy compatibility with the current development toolchain while retaining the release toolchain contract.

## Compatibility

- No intentional breaking API or configuration changes.
- Existing `config.toml`, `models.toml`, token-usage data, and model files remain compatible.
- Existing Conformance Console history is preserved. Older Inspect and Compare rows that stored no result remain unchanged; new runs record PASS or FAIL.

## Install

### Prebuilt binary

```bash
curl -fsSL -o gguf-switchboard \
  https://github.com/pradeepgudipati/gguf-switchboard/releases/download/v0.1.7/gguf-switchboard-linux-amd64
chmod +x gguf-switchboard
```

See **Assets** for Linux and macOS builds plus `checksums.txt`.

### Upgrade from v0.1.6

```bash
cd gguf-switchboard
git checkout main && git pull
./deploy.sh
```

Existing runtime configuration and model registries are preserved.

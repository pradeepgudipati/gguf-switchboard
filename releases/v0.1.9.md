# gguf-switchboard v0.1.9

**Faster, more honest model loads plus a smoother deploy story.** This release adds per-model throughput tracking, retries slow VRAM-spilling loads instead of rolling back, hardens the vLLM runtime and `deploy.sh`, and tightens the release pipeline with preflight checks and a local release driver.

## What's new

### Observability

- Per-model generation throughput: every non-streaming request records a tokens/second sample (skipping trivial requests), with a median over the last 14 days (falling back to 90 days when sparse) and a per-day trendline.
- `/v1/models` and `/v1/models/{id}` gain an optional `tokens_per_sec` field; new `GET /v1/models/{id}/throughput` returns the figure plus the daily trend.
- The Swagger model dropdown shows `~N tok/s` after the size.
- Endpoint conformance tests (`tests/conformance_endpoints.rs`, 14 tests) pin chat/completions, legacy completions, embeddings cardinality, `/v1/models` + `/health` shapes, the OpenAI error envelope, SSE framing with `[DONE]`, drain-timeout 409, and rollback-after-failed-switch over HTTP. Test fixtures are hermetic (own temp dir, immune to stray `models.toml` files).

### Reliability

- Slow loads that outrun `startup_timeout` are now treated as VRAM pressure in disguise (weights + KV cache spill to CPU and crawl past the deadline) and retried with reduced fit — context first, then `-ngl` — instead of rolling straight back to the previous model. Applies to the legacy path and all four fit/vLLM planner gates.
- `models search` GGUF table restores the binary `SUPPORTED` Yes/No verdict alongside the continuous `FIT` score.
- `models list`/`delete` resolve the local registry the same way `pull` does (deployed registry, then `./models.toml`, then `config.toml models_file`), so pulled models no longer show as `(unregistered)`.

### vLLM runtime

- Replaced `vllm --version` probes with an `importlib.metadata` import probe (the CLI entrypoint infers device type at startup and crashes on healthy installs with `Can't initialize NVML` / `Failed to infer device type`); probe failures now carry actionable GPU/driver guidance.
- Python capped at `<3.13`, `uv.lock` committed (vLLM 0.28.0), sync `--frozen`.
- `VLLM_RELEASE_CHANNEL` `stable` (locked, default) / `nightly` (re-resolve vs PyPI), mirroring `LLAMA_RELEASE_CHANNEL`.
- Non-fatal `nvidia-smi` / `CUDA_VISIBLE_DEVICES` preflight warnings.

### Deployment

- `deploy.sh` stash hygiene: prints stashed files, auto-pops after a clean pull, loud recovery instructions on conflict; `vllm-runtime/.venv` ignored.
- Stray-registry merge uses a `ggs`-readable staged copy with per-file ok/FAILED reporting (fixes `/tmp Permission denied` from root-owned mktemp files).
- After a HEAD-moving `git pull`, the fresh `deploy.sh` is re-executed (a running bash script otherwise keeps executing stale buffered bytes); opt-out with `GGUF_SWITCHBOARD_NO_REEXEC=1`.
- Opt-in `newgrp ggs` at the end of a successful deploy.
- Deployed `/opt` registry wins whenever it exists (scan-dir second, CWD last), so pulls from checkouts stop creating strays.
- Self-healing of root-owned `llama.cpp` build and cargo `target/` dirs.
- `scripts/update-llama-cpp.sh`, `setup-vllm.sh`, and `test-runtime-updates.sh` refined alongside the deploy flows.

### Release pipeline

- `scripts/check-release-preflight.sh` fails fast on malformed tags, missing/empty `releases/<tag>.md` notes, and `Cargo.toml`/tag version drift; covered by `scripts/test-release-preflight.sh` (part of `ci.sh`/`precommit.sh`).
- `scripts/release.sh vX.Y.Z` runs preflight + gate + tag + build + publish locally.
- `.forgejo/workflows/release.yml` runs preflight before the native amd64/arm64 build legs and Forgejo Releases publish (replaces Woodpecker).

### API consoles and docs

- Conformance button moved to the header; model picker stacks below the status tiles.
- Swagger UI hides the unused Schemas section.
- README positioning and sharing sharpened; header screenshots refreshed.

## Compatibility

- No intentional breaking API or configuration changes.
- Existing `config.toml`, canonical `models.toml`, usage data, throughput history, conformance history, and model files remain compatible.
- Throughput tracking adds a `model_throughput` table retained for 90 days (prune-on-open plus opportunistic prune-on-insert); it is created automatically on first run.

## Install

### Prebuilt binary

```bash
curl -fsSL -o gguf-switchboard \
  https://github.com/pradeepgudipati/gguf-switchboard/releases/download/v0.1.9/gguf-switchboard-linux-amd64
chmod +x gguf-switchboard
```

See **Assets** for Linux builds plus `checksums.txt`.

### Upgrade from v0.1.8

```bash
cd gguf-switchboard
git checkout main && git pull
./deploy.sh
```

Existing runtime configuration and model registries are preserved.

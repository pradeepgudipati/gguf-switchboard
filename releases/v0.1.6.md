# gguf-switchboard v0.1.6

**One model endpoint, two inference backends.** gguf-switchboard now routes GGUF models through llama.cpp and safetensors models through vLLM while preserving its OpenAI- and Anthropic-compatible API surface and single-resident-model lifecycle.

## What's new

### vLLM backend and unified model routing

- Added a vLLM backend for safetensors models, including process lifecycle, health checks, request forwarding, and backend-specific model metadata.
- A single registry alias can define GGUF and vLLM sources. Runtime selection prefers a compatible vLLM source when the hardware-fit gate passes and falls back to GGUF when appropriate.
- `GET /v1/models` now reports the selected backend and relevant vLLM parameters.
- `models search`, `models files`, and `models pull` understand vLLM repositories, explain hardware-fit exclusions, avoid re-downloading registered repositories, and resolve the installed configuration when invoked outside the install directory.

### Default dual-backend installation

- `deploy.sh` now installs llama.cpp and vLLM by default and generates aligned service and registry configuration.
- Deployment rejects a vLLM model entry without a usable model source instead of installing a configuration that cannot start.
- Added the isolated `vllm-runtime` Python environment and setup automation while preserving existing configuration during upgrades.

### Reranking API

- Added reranker model discovery, metadata, validation, lifecycle handling, and backend execution.
- Added `POST /v1/rerank` for document reranking, with model-kind guards that reject incompatible chat or embedding models.
- Registry expansion automatically applies reranking flags where llama.cpp requires them.

### Tool-calling and template conformance

- Added `/swagger-ui/conformance.html` and `/v1/conformance/*` endpoints to inspect whether tool calls are structured, dumped into plain text, or leaked into reasoning output.
- The console can resolve the actual Jinja-rendered prompt, run a fixed conformance battery, and compare two models side by side.
- Models can set `chat_template_file`, `reasoning_format`, and a minimum `ctx` floor independently.
- Swagger UI model changes now update open request bodies correctly, and UI assets use `Cache-Control: no-cache` so fixes are not hidden by stale browser content.

### Operations and capacity management

- Added `ggs stop` and `ggs restart` service commands.
- Added model-aware NVIDIA monitoring that identifies switchboard-managed `llama-server` processes while preserving standard `nvidia-smi` output.
- Improved embedding admission control and VRAM-aware batch profiles, including multi-GPU fit planning.
- Expanded CLI help and command-mistake hints for model and registry operations.
- Refreshed deployment smoke tests and platform installation documentation.

### CI and release reliability

- Pinned Rust 1.88 across CI, Docker, and release builds and fixed aarch64 cross-compilation dependencies.
- Added a Woodpecker Linux release pipeline and retained GitHub Actions as the manual cross-platform release fallback.
- Hosted GitHub CI now runs on pull requests without repeating the same checks after merge, and documentation-only changes skip the hosted Rust gate.
- Release checksum generation now handles artifact directories safely.

## Install

### Prebuilt binary

```bash
curl -fsSL -o gguf-switchboard \
  https://github.com/pradeepgudipati/gguf-switchboard/releases/download/v0.1.6/gguf-switchboard-linux-amd64
chmod +x gguf-switchboard
```

See **Assets** for Linux and macOS builds plus `checksums.txt`.

### Upgrade from v0.1.5

```bash
cd gguf-switchboard
git checkout main && git pull
./deploy.sh
```

Existing `config.toml` and `models.toml` are preserved.

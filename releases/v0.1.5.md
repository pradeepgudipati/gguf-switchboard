# gguf-switchboard v0.1.5

**llama-swap alternative in Rust** — OpenAI- and Anthropic-compatible GGUF runtime with memory-pressure eviction, OOM context fallback, and built-in usage tracking.

## What's new

### Tool-call capability verification

`capabilities: ["tools"]` was previously a static guess inferred once from Hugging Face tags — never checked against how the model actually behaves once served. A model could advertise `tools` and still return malformed tool-call JSON to an agentic client like OpenCode, with no signal beyond a downstream parse error.

- On load, models tagged `tools` are now probed with a real tool call (a trivial `echo` function) before they're marked ready. The verdict — verified, failed, or skipped — is tracked in memory and re-checked on every reload.
- `POST /v1/chat/completions` now rejects tool-bearing requests to a model that failed its probe with a clear `400`, instead of silently forwarding a request that will come back malformed.
- `GET /v1/models` and `GET /v1/models/{id}` expose the verdict as `tools_verified: true|false`, so a caller can filter before ever sending a tool-bearing request.
- Fixed a known llama.cpp defect where `tool_calls[].function.arguments` is sometimes returned as a JSON object instead of the OpenAI-required JSON string — normalized on every chat response (streaming and non-streaming), not just inside the probe.

### Model search: FIT / SPEED / PRECISION scoring

`models search` and `models files` replace the old binary "Supported Yes/No" column with three continuous scores:

- **FIT** (0–100) — how well a quant's memory footprint fits your VRAM
- **SPEED** — a memory-bandwidth-grounded throughput estimate, with a `--ram-bandwidth-gbps` override
- **PRECISION** — quality-loss scoring sourced from published k-quants perplexity data
- Pull-command suggestions now split into "fastest" vs. "least-lossy," plus a new **BALANCED** recommendation at the size midpoint between them
- Full methodology in [`docs/QUANT_SCORING.md`](../docs/QUANT_SCORING.md)

### Faster, safer model switching

- New `switch_strategy` config (default `unload_first`) stops the resident `llama-server` *before* starting the next one. Previously the new model started while the old one still held the GPU, so `auto_ngl` / the fit planner planned against leftover VRAM and `llama-server` OOM'd into the context/`-ngl` fallback ladder — several spawns per switch, then a partially CPU-resident model. `load_first` restores the old behavior for multi-GPU boxes. Failed switches still roll back by re-loading the previous model.
- Hardened `unload_first`: SIGTERM failures are now logged and retried with SIGKILL instead of silently swallowed; a new drain wait polls until the old process is dead and CUDA has actually reclaimed VRAM before the next model loads; unload failure is now fatal to the switch instead of continuing on a stale backend entry.
- Optional `prewarm_recent_models` keeps recently used GGUFs in the page cache so switching back is served from RAM.
- `llama-server` stdout is no longer piped-but-unread (could stall a noisy server mid-load); `--version` is cached per binary instead of re-run on every load.

### Observability

New per-model metrics: `gguf_switchboard_model_switch_seconds`, `..._switch_phase_seconds` (drain / unload_previous / plan / spawn_to_healthy / rollback), `..._model_load_seconds{result}`, `..._model_load_attempts_total`, `..._model_last_load_seconds`, `..._request_model_wait_seconds`, `..._request_model_hit_total`, `..._model_switches_total{from,to,trigger}`, `..._model_unloads_total{reason}`, `..._loaded_model_info{model}`. `/status` now exposes `last_switch`. Load/inference histograms extend beyond 10 s. `gguf_switchboard_inference_latency_seconds` no longer includes model load time and, for streams, is observed when the stream ends rather than when headers are sent; `active_requests` / `streaming_requests` gauges no longer leak when a request fails before the backend call.

### Embeddings fixes

- Per-model `batch_size` / `ubatch_size` config, auto-configuring `llama-server -b`/`-ub` for embedding models (default 2048)
- Oversized embedding requests are now split into multiple batches instead of failing with "input exceeds physical batch size"
- Fixed embedding input cardinality being flattened on multi-input requests

### Misc

- `deploy.sh` now shallow-clones llama.cpp on first install

## Install

### Prebuilt binary (Linux)

```bash
curl -fsSL -o gguf-switchboard \
  https://github.com/pradeepgudipati/gguf-switchboard/releases/download/v0.1.5/gguf-switchboard-linux-amd64
chmod +x gguf-switchboard
```

See **Assets** for `linux-arm64`, macOS builds, and `checksums.txt`.

### Upgrade from v0.1.4

```bash
cd gguf-switchboard
git checkout main && git pull
./deploy.sh
```

Existing `config.toml` and `models.toml` are preserved.

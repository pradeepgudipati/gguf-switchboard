# gguf-switchboard v0.1.3

**llama-swap alternative in Rust** — OpenAI- and Anthropic-compatible GGUF runtime with memory-pressure eviction, OOM context fallback, and built-in usage tracking.

## What's new

### Model management CLI (Hugging Face)

New `models` subcommands for one-command GGUF discovery, download, and registration:

- **`models search <query>`** — search the Hugging Face Hub for GGUF models; shows repo, file count, context length, and architecture
- **`models files <repo-id>`** — list `.gguf` files in a repo with size and quantization label; shows multimodal projectors separately
- **`models pull <repo-id> --quant QUANT`** — download, validate, and register a model in one step: streams with progress, validates GGUF header/metadata, generates an alias, and merges into `models.toml`
- `--dir` to override the destination directory, `--registry` to target a specific registry file
- `HF_TOKEN` environment variable support for gated models
- `models search` shows model size in MB and context length in tokens
- `gs` shell alias — `deploy.sh` offers to add it automatically (Linux bash/zsh); manual setup for macOS zsh and Windows PowerShell

### Anthropic Messages API

- `POST /v1/messages` — full Anthropic Messages API compatibility (stream + non-stream)
- Translates Anthropic request/response format onto the loaded `llama-server` OpenAI backend

### Responses API function tools

- Strict Responses streaming events (`response.function_call_arguments.delta`, `.done`)
- Function tool translation: `tools` → Chat Completions format, `tool_calls` → Responses format
- Fragmented argument reassembly across stream chunks
- Per-tool-call index tracking in streaming mode

### Auto GPU layers (`auto_ngl`)

- Opt-in `auto_ngl` in `config.toml`: at model load, picks `-ngl` from free VRAM (nvidia-smi) + GGUF file size
- Manual `ngl` / `extra_args` still override — `ngl_pinned` prevents auto-rewrite

### Swagger UI improvements

- Hides incompatible endpoints based on selected model kind (chat vs embedding)
- Live model dropdown from `/api-docs/openapi.json`
- Rich model cards from HF metadata (description, context length, VRAM, capabilities)

### GGUF rescan & enrichment

- `sync-hf-metadata` CLI enriches empty `description` / `max_context_length` / `min_vram_gb` / `capabilities` / `hf_repo` from Hugging Face
- Automatic HF sync on server launch and `POST /v1/models/refresh`
- Configurable periodic rescan watcher (`models_rescan_interval_secs`, default daily)
- `POST /v1/models/refresh` hot-swaps the live scheduler without restart

### Embeddings fixes

- `--embeddings` flag auto-added to `llama-server` for embedding models
- `encoding_format` defaults to `"float"` to prevent null serialization to backends
- Null optionals omitted from `EmbeddingRequest` to prevent 500s from local-ai

### Reliability

- Scheduler load-then-unload with rollback on failed switches
- OOM-only context fallback via stderr classification
- Per-model request draining before model switches
- Fallback dir resolution in `expand()` prevents crash when `models_dir` missing

## Install

### Prebuilt binary (Linux)

```bash
curl -fsSL -o gguf-switchboard \
  https://github.com/pradeepgudipati/gguf-switchboard/releases/download/v0.1.3/gguf-switchboard-linux-amd64
chmod +x gguf-switchboard
```

See **Assets** for `linux-arm64`, macOS builds, and `checksums.txt`.

### Upgrade from v0.1.2

```bash
cd gguf-switchboard
git checkout main && git pull
./deploy.sh
```

Existing `config.toml` and `models.toml` are preserved.

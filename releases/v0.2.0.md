# gguf-switchboard v0.2.0

**Model registration that actually sticks, plus constrained-output passthrough.** This release adds `ggs models register` and `ggs models clean`, makes `deploy.sh` register new GGUF files automatically, forwards `grammar` / `json_schema` to llama.cpp, reports token usage on all streaming endpoints, and hardens several deploy paths.

## What's new

### Model management

- New `ggs models register [<#|name>...]` adds GGUF files found on disk but missing from `models.toml` (all of them, or just the given `#`/names). Existing entries are preserved, new ones get generated aliases, and stale entries left behind by a removed model directory are replaced.
- New `ggs models clean [--yes]` deletes unregistered duplicate copies (same filename and size as a registered file in another scan directory). The registered copy is never touched; it lists what it will delete and asks first.
- `ggs models list` now hints at `register`.
- `./deploy.sh` runs `models register` against the canonical registry when it keeps an existing `models.toml`, so newly added GGUF files no longer show as `(unregistered)` after a deploy.

### API

- Chat completions forward `grammar` (GBNF) and `json_schema` unchanged to the backend, alongside the already-forwarded `response_format`, so llama.cpp can constrain output to a schema.
- The Responses API accepts and forwards `grammar`.
- Token usage is reported on all streaming endpoints.
- `docs/COMPATIBILITY.md` no longer lists JSON mode as untested.

### Reliability and deployment

- Fit-planner flag handling strips flag values as pairs and dedupes stale batch flags on expand.
- `deploy.sh`: stashes a dirty llama.cpp tree instead of aborting, offers to keep the existing llama.cpp runtime when an update fails, repairs root-owned files on `ggs` service paths, no longer leaves an `exec newgrp` subshell (prints a hint instead), shows the vLLM release check banner, and probes deploy-user writability with a real file.

## Compatibility

- No intentional breaking API or configuration changes; the new request fields are optional.
- Existing `config.toml`, `models.toml`, usage data, and model files remain compatible.
- The service user (`ggs`) must be able to read every directory in `models_dir`. A refresh drops registry entries whose files it cannot see, for example models under a private `/home/<user>` directory. Keep models in `/var/lib/gguf-switchboard/models`.

## Install

### Prebuilt binary

```bash
curl -fsSL -o gguf-switchboard \
  https://github.com/pradeepgudipati/gguf-switchboard/releases/download/v0.2.0/gguf-switchboard-linux-amd64
chmod +x gguf-switchboard
```

See **Assets** for Linux builds plus `checksums.txt`.

### Upgrade from v0.1.9

```bash
cd gguf-switchboard
git checkout main && git pull
./deploy.sh
```

Existing runtime configuration and model registries are preserved.

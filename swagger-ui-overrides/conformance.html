Run a chat request and see exactly where the tool call ended up: a proper structured tool_calls entry, a JSON blob the model dumped as plain text, JSON that leaked into reasoning_content, or nothing at all. Body shape matches /v1/chat/completions — paste straight from Swagger.

Shows the actual prompt string a model's Jinja chat template resolves to for the given messages/tools — the direct way to catch a broken or missing embedded template (GLM/DeepSeek- style models are the recurring offenders) instead of guessing from garbled output.

Runs 4 fixed scenarios against one model — single tool call, parallel tool calls, tool call with reasoning, and a multi-turn tool-result summary — and scores each pass/fail instead of dumping raw JSON.

Fires the same request (or the same battery case) at two models, one after another. The switchboard holds one model resident at a time, so this is two full model swaps back to back — expect it to take as long as loading each model, not an instant response.
